# Testbed tools

Three tools for scale and load tests. Run every command from the repository root.

## Synthetic S3 source

`synth.py` is an anonymous, read-only S3 server that stores nothing. It serves path-style
ListObjectsV2 (`prefix`, `delimiter`, `start-after`, `continuation-token`, `max-keys`,
`encoding-type`), HEAD and GET (with `Range`, `If-Match` and `If-None-Match`). Signatures are not
checked. Keys, sizes, ETags and bytes come from the layout and the seed, so a key always gives the
same result. Listings find the cursor with a binary search over the virtual key sequence and never
build the key list, so a layout can hold billions of keys.

```bash
uv run scripts/testbed/synth.py --layout 49x50000x20 --port 9100 \
  --sizes log:1k:1m --manifests md5,sha256 --latency-ms 20 --page-cap 1000 --rate 500
```

- `--layout BxFxN`: buckets, folders per bucket, files per folder. Keys are
  `<folder>/<file>`. Names use zero padded numbers, so the key order follows the numbers.
- `--bucket-pattern`, `--folder-pattern`, `--file-pattern`: names with one `{}` for the number.
  Defaults are `bucket-{}`, `folder-{}` and `file-{}.dat`.
- `--sizes`: `fixed:N`, `uniform:A:B` or `log:A:B`. Sizes accept `k`, `m` and `g` suffixes.
- `--manifests`: adds `MD5SUMS` and/or `SHA256SUMS` to every folder, in `md5sum` and `sha256sum`
  format, matching the generated files.
- `--seed`: changes all content. `--latency-ms`: delay per request. `--page-cap`: upper limit
  for `max-keys`. `--rate`: requests per second, above it the server answers 503 `SlowDown`.

The ETag is the plain hex MD5 of the generated bytes, so listing a page costs the hashing of
its objects. Keep sizes small when you list large pages. Results of the last 100000 hashes
are kept (`--cache-size`). A manifest is built in memory, so keep files per folder moderate.

Example: `aws s3api list-objects-v2 --no-sign-request --endpoint-url http://127.0.0.1:9100
--bucket bucket-00 --prefix folder-00007/`.

## Load generator

`loadgen.py` runs PUT, multipart upload, GET, ranged GET and HTTP downloads with a thread
pool. It prints operations, errors, bytes, seconds, ops per second, MiB per second, p50 and p99
latency (`--json` prints one JSON line). The exit code is 1 when any operation failed.

```bash
uv run --with boto3==1.43.99 scripts/testbed/loadgen.py put --s3-url http://127.0.0.1:43002 \
  --bucket load --prefix run1/ --access-key "$KEY" --secret-key "$SECRET" --count 1000 --size 4m
uv run --with boto3==1.43.99 scripts/testbed/loadgen.py multipart ... --size 64m --part-size 8m
uv run --with boto3==1.43.99 scripts/testbed/loadgen.py get ... --prefix run1/ --count 1000
uv run --with boto3==1.43.99 scripts/testbed/loadgen.py range ... --prefix run1/ --range-size 64k
uv run scripts/testbed/loadgen.py http --rest-url http://127.0.0.1:43000 \
  --path w3id/example --path /api/v1/some/download --token "$TOKEN" --count 500
```

`get` and `range` list up to `--count` keys under `--prefix` first, then read them in turn.
`http` follows redirects, so it also measures w3id downloads. Use `--anonymous` against the
synthetic source. Part sizes below 5m are refused. Use a new `--prefix` for every `put` run.

## Local five node realm

`scripts/cluster_start.sh` deletes its whole deployment root before it starts. Always point it
at a dedicated directory below `target/`. It refuses the repository root and `$HOME`.

```bash
CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 \
  nice -n 19 ionice -c3 cargo build --workspace --release --locked
ARUNA_TEST_DEPLOY_ROOT="$PWD/target/test-deploy-distributed" \
ARUNA_TEST_DEPLOY_SKIP_BUILD=1 ARUNA_TEST_DEPLOY_BASE_PORT=44000 \
  nice -n 19 ionice -c3 bash scripts/cluster_start.sh --node-count 5
```

- The script builds with no limits unless `ARUNA_TEST_DEPLOY_SKIP_BUILD=1` is set, so build
  first with the repository limits as shown (use `cargo-safe` if you have it) and skip the build.
- Keep the root named `target/test-deploy-distributed` and keep cargo target directories named
  `target`. Do not use a prefix or suffix for them.
- URLs and ports of every node are in `$ARUNA_TEST_DEPLOY_ROOT/summary.txt`, the admin login is in
  `credentials.txt`. Set a different `ARUNA_TEST_DEPLOY_BASE_PORT` to avoid clashes with another
  cluster.
- Stop it with `bash scripts/cluster_stop.sh` (or `just stop`), or press Ctrl-C in the terminal.

## Checks

```bash
uv run --with pytest --with boto3==1.43.99 pytest scripts/testbed
```

The checks cover deterministic paging, `start-after` and continuation at page borders,
delimiters, HEAD and GET agreement, ranges, manifests, limits, a layout of 10^12 keys, the
load generator statistics and a real boto3 client. They need no network beyond loopback.
